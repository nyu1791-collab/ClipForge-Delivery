# 制作と納品管理の役割

## Deliveryの役割

Deliveryは完成済み動画・字幕・タイトルを案件にまとめ、納品用ZIPと納品記録を作る独立したローカルアプリです。制作の開始、外部Runの監視、モデルへの要求、動画の再描画は制作アプリ側で行います。

ClipForgeとの受け渡しは、PCへ回収した `manifest.json` または完成動画フォルダ経由です。DeliveryはClipForgeのPython、ソースコード、APIを直接呼び出しません。`CLIPFORGE_DIR` や `CLIPFORGE_PYTHON` の設定は不要です。

## 通常の流れ

1. 制作アプリ側で制作し、完成物をPCへ回収する。
2. Deliveryで案件を登録する。
3. 完成動画フォルダ、汎用の素材一覧、ClipForgeの `manifest.json` を取り込む。
4. 動画・字幕・タイトル・費用・納品状況を案件画面で整理する。
5. 必要な動画をZIPにまとめ、ユーザーの選んだ方法で納品する。

形式の詳細は [素材の一括取り込みと納品](HANDOFF.md) にあります。

## 無駄な再処理を省く

- 同じ動画の再取り込みではコピー済み素材を再利用します。
- 字幕・制作記録だけが変わった場合は、動画をコピーし直さず付随ファイルを更新します。
- 元動画と元字幕は取り込み元に保持します。Delivery内の字幕手修正版は別ファイルとして扱います。
- 一部の素材が見つからなくても、取り込める残りの素材を続行します。
- タイトルや納品記録の編集から、制作をやり直すことはありません。

## 目標と実際の状態

本数・尺・演出数は制作時の目安です。Deliveryは不足を理由に動画を除外したり、モデルへ自動で作り直しを要求したりしません。取得済みの完成物をそのまま整理します。

素材不存在など実際に取り込めなかったものは理由を表示します。品質監査や完成動画の全デコード検査を追加する工程はありません。
